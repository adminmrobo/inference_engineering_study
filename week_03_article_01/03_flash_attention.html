3F 병목 진단실

느린 곳을 찾는다 — 계산이 막혔나, 메모리 통로가 막혔나

인턴 시아 · 공정 안내

여기는 3F 병목 진단실이에요. 계산이 막혔나, 메모리 통로가 막혔나. 이 해설은 이 층의 기계 2대를 맡았어요. 번호를 누르면 그 칸으로 내려갑니다.

    그래서 이 편에서 돌리는 다이얼은?

    모델은 그대로, 계산 순서만 바꿔 빨라지는 다이얼입니다. 모델 구조(어텐션)와 GPU 구조(메모리 계층)를 둘 다 알아야 돌릴 수 있어요.

    1. ① 목표 정하기빨리(지연시간) · 많이(처리량) · 싸게(비용) 중 무엇을 먼저 지킬까
    2. ② 모델 성질 보기질문 읽기(프리필)는 계산이 막히고, 한 토큰씩 쓰기(디코드)는 메모리 통로가 막힌다
    3. ③ 기계 맞추기모델이 VRAM에 들어가나, 메모리 대역폭은 충분한가
    4. ④ 다이얼 돌리기아래 다섯 다이얼을 목표에 맞춰 조절한다
    5. ⑤ 재고 병목 찾기계기판(TTFT · TPS · P99)과 루프라인으로 막힌 곳을 찾고 → 다시 ②로
    • 배치한 번에 몇 주문을 함께 돌릴까 — 많이 묶을수록 처리량은 오르고, 주문 하나의 기다림은 길어질 수 있다
    • 정밀도숫자를 몇 자리로 담을까 (양자화) — 작게 담으면 메모리와 속도에서 이득, 품질은 다시 재 봐야 한다
    • KV 캐시앞 토큰의 메모를 어떻게 쌓고 다시 쓸까 — 메모가 길고 많을수록 GPU 메모리를 차지한다
    • 나눠 싣기모델과 공정을 GPU 여러 대에 어떻게 나눌까 (병렬화 · 분리) — 한 대에 안 들어가거나 더 빨라야 할 때 쓴다
    • 계산 방식이 편계산 방식 다이얼의 대표 사례 — 타일로 쪼개 작은 창고(SRAM) 안에서 끝내고 큰 창고(HBM) 왕복을 줄입니다.

    불이 켜진 단계와 다이얼이 이 편이 맡은 자리입니다. 회색은 다른 편에서 다룹니다.

    번개 어텐션 —
    창고를 덜 오가면 빨라진다

    계산을 줄이지 않고도, 어텐션을 몇 배 빠르게 만들 수 있을까?

    트랜스포머의 어텐션은 문장이 길어질수록 시간과 메모리가 길이의 제곱으로 늘어난다. 많은 연구가 계산을 덜 하는 근사 방법을 만들었지만, 실제 시계로 재면 빨라지지 않는 경우가 많았다. 이 논문은 범인을 계산이 아니라 메모리를 오가는 횟수에서 찾고, 답을 바꾸지 않는 정확한 어텐션을 더 빠르고 더 가볍게 만들었다.

    Tri Dao, Daniel Y. Fu, Stefano Ermon, Atri Rudra, Christopher Ré (2022). FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness. arXiv:2205.14135v2.

    7.6×GPT-2 어텐션 계산 속도 향상 [1]
    40.3 → 4.4 GB창고 메모리 읽고 쓰기 (GPT-2 medium) [2]

    논문 속 용어의 별명

    본문은 별명으로 쓰고, 원래 이름은 카드와 괄호에만 둔다.

    창고 메모리
    논문 이름: HBM (high bandwidth memory)
    크지만(40~80GB) 실험대에서 멀다. 1초에 1.5~2.0TB를 나른다.
    실험대 메모리
    논문 이름: SRAM (on-chip)
    작지만(작업대 하나 192KB) 바로 옆. 약 19TB/s로 약 10배 빠르다.
    왕복 횟수
    논문 이름: IO, HBM accesses
    창고에서 읽고 창고에 쓰는 양. 이 논문의 주인공 지표.
    쟁반 나누기
    논문 이름: tiling
    큰 행렬을 실험대에 들어가는 블록으로 쪼개 하나씩 처리.
    다시 계산하기
    논문 이름: recomputation
    중간 결과를 창고에 보관하지 않고, 필요할 때 실험대에서 다시 만든다.
    한 번에 몰아 하기
    논문 이름: kernel fusion
    재료를 한 번 가져와 곱셈·소프트맥스·마스킹을 쉬지 않고 이어서.

    1질문

    왜 근사 어텐션은 빨라지지 않았나

    모델: 표준 어텐션 softmax(QKᵀ)V논문: 1장, 그림 1

    기존 생각

    느린 이유는 계산량(FLOP)이 길이 N의 제곱이라서다. 그러니 계산을 줄이는 근사(희소·저랭크)를 쓰면 빨라진다.

    ➜

    이 논문

    GPU에서는 계산보다 메모리를 오가는 일이 병목이다. 계산은 그대로 두고 창고 메모리 왕복을 줄이면, 정확한 답 그대로 빨라진다. 이것을 IO-인지(IO-aware) 설계라 부른다.

    연구실에서는

    실험대는 작지만 손만 뻗으면 닿고, 시약 창고는 크지만 복도 끝에 있다. 실험이 느린 이유가 손이 느려서가 아니라 복도를 너무 자주 왕복해서라면, 손을 빠르게 해 봐야 소용없다.

    모델에서는

    GPU의 계산 속도는 메모리 속도보다 빠르게 늘었다(논문 2.1). 그래서 소프트맥스·마스킹·드롭아웃 같은 연산은 메모리 바운드다. 시간은 계산 횟수가 아니라 창고를 읽고 쓴 양이 정한다.

    메모리 계층 — 그림 1 왼쪽의 숫자

    A100 기준으로 논문 2.1은 HBM 40~80GB(1.5~2.0TB/s), 스트리밍 멀티프로세서 108개마다 SRAM 192KB(약 19TB/s 추정)라고 적었다. 20MB는 192KB × 108을 합친 크기다.

    ① S = QKᵀQ, K를 읽어 계산하고 N×N 행렬 S를 창고에 쓴다
    ② P = softmax(S)S를 다시 읽고 P를 창고에 쓴다
    ③ O = PVP와 V를 읽어 O를 창고에 쓴다

    왜 이게 느린가

    1. N = 1024이면 어텐션 행렬 S 하나가 약 100만(1,048,576) 칸이다. 머리(head) 하나, 문장 하나에.
    2. 표준 구현(논문 알고리즘 0)은 이 큰 행렬을 창고에 쓰고, 다시 읽고, 또 쓴다. 왕복 양이 N²에 비례한다.
    3. 마스킹·드롭아웃을 따로 하면 왕복이 더 늘어난다. 학습할 때는 역방향을 위해 P를 보관까지 해야 한다.

    딥러닝 실무에서 비슷한 작업

    행렬 곱셈 라이브러리는 오래전부터 블록 단위로 캐시를 아껴 쓴다(논문 2장: 데이터베이스 조인, 이미지 처리, 수치 선형대수). 번개 어텐션의 새로움은 소프트맥스처럼 행 전체를 봐야 하는 연산까지 블록으로 쪼갠 데 있다.

    비유의 한계: 실제로는 수천 개의 스레드가 동시에 여러 쟁반을 처리한다. 한 사람이 쟁반을 나르는 그림은 순서만 보여 준다.

    3결과 ①

    창고 왕복을 몇 배 줄이나

    모델: 정리 2 — Θ(Nd+N²) vs Θ(N²d²/M)논문: 3.2절, 그림 2 왼쪽

    연구실에서는

    쟁반(실험대 크기 M)이 클수록 한 번에 많이 가져와 왕복이 준다. 큰 결과물을 창고에 내려놓지 않고 실험대에서 끝내면 더 준다.

    모델에서는

    표준 어텐션의 창고 접근은 Θ(Nd + N²). 번개 어텐션은 Θ(N²d²/M). 보통 d = 64~128, M ≈ 100KB이므로 d²가 M보다 몇 배 작아 접근이 몇 배 준다.

    머리 차원 d

    행동으로 보기 — 조수가 쟁반을 나른다

    원문 수치 — 그림 2 왼쪽 (GPT-2 medium, 길이 1024, d=64, 머리 16, 배치 64, A100, 순방향+역방향)

    표준66.640.341.7
    번개 어텐션75.24.47.3

    표를 읽는 법

    1. 번개 어텐션은 계산(GFLOPs)이 더 많다(역방향에서 다시 계산하므로).
    2. 그런데 창고 왕복이 40.3 → 4.4GB로 약 9분의 1이 되자, 시간은 41.7 → 7.3ms로 줄었다.
    3. 논문의 결론: 창고 접근량이 실행 시간을 정하는 주된 요인이다.
    4. 이 칸의 한계: 블록을 키우면 왕복은 계속 줄지만, 실험대에 안 들어가거나 계산이 병목이 된다 → 모형 실험실에서 확인.
    수식으로 보기 — 정리 2의 아이디어

    실험대 크기 M에서 K, V 블록을 Θ(M) 크기로 올린다(알고리즘 1의 6줄). K·V 블록마다 Q 전체를 한 바퀴 돈다(8줄). 블록 수는 Tc = N/Bc = Θ(Nd/M)이고, 한 바퀴에 Θ(Nd)를 읽으므로 전체는 Θ(Nd · Nd/M) = Θ(N²d²/M).

    하한(명제 3): 모든 M ∈ [d, Nd]에서 o(N²d²/M)로 정확한 어텐션을 계산하는 알고리즘은 없다. M = Θ(Nd)이면 입력 Q, K, V를 읽는 것만으로 Ω(Nd)이 필요하기 때문이다.

    이 페이지의 계산기는 상수까지 넣은 단순화 식이다: 표준 4Nd+4N² (순방향), 번개 2Nd+3Nd·Tc, Bc = ⌈M/(4d)⌉ (원소 2바이트). 설명용이다.

    조수(하루)

    그림 2 왼쪽에서 계산은 66.6에서 75.2 GFLOPs로 늘었는데, 시간은 41.7ms에서 7.3ms로 줄었어요.

    4결과 ②

    쪼개서 계산해도 답이 똑같다

    모델: 온라인 소프트맥스 (m, ℓ 통계)논문: 3.1절, 알고리즘 1의 10~12줄, 정리 1

    연구실에서는

    시료를 쟁반 단위로 측정하면서 실험 노트에 지금까지의 최댓값과 보정한 합계 두 줄만 적는다. 새 쟁반에서 더 큰 값이 나오면 앞의 합계를 그 비율만큼 고쳐 적는다.

    모델에서는

    소프트맥스는 행 전체의 합으로 나누므로 블록으로 쪼개기 어렵다. 블록마다 최댓값 m과 지수합 ℓ을 들고 다니며 em−mnew로 앞의 결과를 고치면, 마지막에 정확히 같은 값이 나온다.

    무엇을 보았나

    1. 점수 12개(한 행의 S)와 값 12개(V의 한 열)를 블록으로 나눠 들어온 순서대로 처리했다.
    2. 노트에는 m과 ℓ, 그리고 지금까지의 출력 o 하나만 있다. N×N 행렬은 어디에도 없다.
    3. 블록 크기를 바꿔도 마지막 o는 전체 소프트맥스와 소수 15자리까지 같다. 이것이 정확한(exact) 어텐션이라는 뜻이다.
    4. 보정 없이 블록별 결과를 평균내면 답이 틀린다. 노트의 보정 한 줄이 핵심이다.

    이 칸의 한계: 이렇게 하면 메모리는 줄지만, 학습할 때 역방향이 P를 필요로 한다 → 다시 계산하기(5단계)로 해결.

    수식으로 보기 — 두 블록 합치기 (논문 3.1)
    m(x) = max(m(x⁽¹⁾), m(x⁽²⁾))
    ℓ(x) = em(x⁽¹⁾)−m(x)ℓ(x⁽¹⁾) + em(x⁽²⁾)−m(x)ℓ(x⁽²⁾)
    Oi ← diag(ℓnew)−1( diag(ℓi) emi−mnew Oi + em̃−mnew P̃ijVj )

    정리 1: 알고리즘 1은 O = softmax(QKᵀ)V를 O(N²d) FLOPs로 돌려주고, 입력·출력 밖에 O(N)의 추가 메모리만 쓴다. 증명은 바깥 반복 j에 대한 귀납법(부록 C). 논문은 이런 합치기를 대수적 집계(algebraic aggregation)라 부른다.

    생성 AI로 치면

    챗봇이 긴 대화 기록을 한꺼번에 읽을 때도 각 단어의 어텐션 행은 길이 N만큼 길다. 온라인 소프트맥스는 그 긴 행을 한꺼번에 펼쳐 놓지 않고 블록으로 읽게 해 준다.

    비유의 한계: 실제 GPU에서는 한 행이 아니라 Br개 행을 묶어 동시에 처리하고, 값도 스칼라가 아니라 d차원 벡터다.

    5결과 ③

    실제 시계와 저울로 잰 결과

    모델: 번개 어텐션 · 블록 희소 번개 어텐션논문: 4장, 표 1·2·4·5·6, 그림 3, 표 20·21

    행동으로 보기 — 고른 길이에서 메모리 저울

    읽을 때 주의할 점

    1. 번개 어텐션의 실행 시간도 여전히 N²로 늘어난다. 계산량은 그대로이기 때문이다. 줄어든 것은 상수(왕복)와 메모리다.
    2. 길이 512~1024 사이부터는 Linformer 같은 근사 방법이 더 빨라진다(교차점). 근사가 쓸모없다는 뜻이 아니다.
    3. 블록 희소 번개 어텐션은 근사 방법이지만, 논문이 아는 모든 구현보다 빨랐다.
    4. 메모리는 길이에 선형, 정확한 어텐션 기준선보다 최대 20배 적다(4.3절).

    6실험실

    모형 실험실 — 기술을 하나씩 켜 보기

    모델: 창고 왕복 + 계산 시간 장난감 모형연구실: 공정 개선 실험

    GPT-2 medium 설정(길이 1024, d=64, 머리 16 × 배치 64 = 1,024개)에서 표준 어텐션부터 시작해 기술을 하나씩 더한다. 한 번에 하나만 바꾼다.

    사다리
    블록 크기 Bc

    행동으로 보기 — 창고 앞 쟁반 더미

    풀이

    1. ① 한 번에 몰아 하기: 마스킹·드롭아웃을 소프트맥스와 한 커널에서 하면 그 연산들의 왕복이 사라진다. 하지만 S, P는 여전히 창고에 쓴다.
    2. ② 쟁반 나누기: S, P를 창고에 쓰지 않는다. 다만 역방향을 위해 P를 보관하면 N² 왕복이 남는다.
    3. ③ 역방향 다시 계산: P 대신 노트(m, ℓ)와 출력 O만 보관하고 역방향에서 P를 실험대에서 다시 만든다. 계산은 늘지만 왕복이 더 준다. 논문은 이것을 일종의 선택적 그래디언트 체크포인팅이라 했다.
    4. 블록 크기: 키울수록 Q를 덜 돈다(Tc가 준다). d=64, 실험대 192KB면 Bc = 384에서 꽉 차고 그 위는 안 들어간다. 논문 그림 2 가운데도 256을 넘으면 다른 요인이 병목이 된다고 했다.

    모형의 한계: 시간 = 창고 바이트 ÷ 1.5TB/s + FLOP ÷ 150 TFLOPS(예시값)로 둘을 단순히 더했다. 실제 GPU는 둘을 겹쳐 처리하고, 스레드 배치·점유율 같은 요인이 더 있다. 그래서 모형 시간과 원문 시간은 다르다.

    7다시 읽기

    연구실 말로 다시 읽기

    한 줄 식: 시간 ≈ 창고 왕복 ÷ 대역폭 + 계산 ÷ 연산 속도

    창고 메모리 ↔ 시약 창고

    크고 멀다. 무엇을 몇 번 오가는지가 실험 시간을 정한다.

    한계: 실제 창고 메모리도 꽤 빠르다(초당 1.5TB). "느리다"는 실험대와 비교한 말이다.

    쟁반 나누기 ↔ 타일링

    실험대에 들어갈 만큼만 가져와 그 자리에서 끝낸다.

    한계: 쟁반 크기는 실험대(SRAM)와 d로 정해지고, 머리 차원이 크면 쟁반이 작아진다(부록 E.5).

    실험 노트 두 줄 ↔ m, ℓ 통계

    최댓값과 보정 합계만 적어도 소프트맥스를 정확히 맞춘다.

    한계: 노트도 행마다 하나씩, 길이 N만큼 필요하다. 그래서 추가 메모리가 0이 아니라 O(N)이다.

    다시 계산하기 ↔ 재계산

    중간 결과를 보관하느니 다시 만드는 편이 빠를 때가 있다.

    한계: 계산이 병목인 연산(큰 행렬 곱)에서는 재계산이 오히려 손해일 수 있다.

    한 번에 몰아 하기 ↔ 커널 융합

    재료를 한 번 가져와 여러 공정을 이어서 한다.

    한계: 논문 방식은 어텐션 변형마다 CUDA 커널을 새로 짜야 한다(5장 한계).

    블록 희소 ↔ 빈 쟁반 건너뛰기

    마스크가 0인 블록은 아예 가져오지 않는다. 왕복이 희소도 s만큼 준다(명제 4).

    한계: 이것은 근사다. 건너뛴 블록의 정보는 쓰지 않는다.

    생성 AI로 치면

    언어 모델의 문맥 창이 길어지려면 N²의 메모리 벽을 넘어야 한다. 이 논문은 GPT-2의 문맥을 1K에서 4K로 늘리고도 Megatron-LM 1K보다 빨리 학습했다(표 4). 코드도 공개했다(github.com/HazyResearch/flash-attention).

    한계: 이 논문은 2022년 A100과 Turing·Ampere GPU 기준이다. 그 뒤 하드웨어와 구현의 변화는 이 페이지에서 다루지 않는다.

    현장에 옮기면

    느린 코드를 고칠 때 먼저 프로파일러로 시간을 재고, 계산이 병목인지 데이터 이동이 병목인지부터 가린다(산술 강도). 메모리 바운드면 계산을 줄이지 말고 이동을 줄인다: 연산 합치기, 블록 처리, 중간 결과 보관 대신 재계산. 한계: GPU 종류마다 SRAM 크기와 대역폭이 달라 속도 향상 폭이 다르다(부록 E.5: RTX 3090은 2.5~4.5배, T4는 더 작음).

    8한 장

    한 장으로

    질문: 왜 근사가 안 빨라지나진단: 창고 왕복방법: 쟁반 나누기 + 노트 + 다시 계산 + 몰아 하기증명: Θ(N²d²/M), 하한결과: 정확하고, 빠르고, 메모리 선형

    핵심 1

    GPU 어텐션의 시간은 계산보다 창고 메모리 왕복이 정한다.

    핵심 2

    블록으로 쪼개고 m, ℓ 노트로 합치면 N×N 행렬 없이 정확한 소프트맥스를 낸다.

    핵심 3

    계산을 더 해도(재계산) 왕복이 줄면 더 빠르다. 그 덕에 더 긴 문맥을 학습할 수 있다.

    읽을 때 주의할 점

    • 번개 어텐션은 근사가 아니다. 답이 같다. 블록 희소판만 근사다.
    • 계산량은 여전히 O(N²d)다. 아주 긴 문장에서는 근사 방법이 더 빠를 수 있다.
    • 속도 향상 배수는 GPU, 머리 차원, 마스킹·드롭아웃 여부에 따라 다르다(부록 E.5: A100에서 대체로 2~4배).
    • 논문이 밝힌 한계: CUDA 커널을 직접 짜야 하고 GPU 구조 사이에 옮기기 어렵다. 여러 GPU 사이의 IO 분석은 앞으로의 과제다.

    모아의 기록장

    • SRAM 약 19TB/s · 20MB, HBM 1.5TB/s · 40GB (그림 1, A100)
    • GPT-2 medium: 창고 R/W 40.3 → 4.4GB, 41.7 → 7.3ms, GFLOPs 66.6 → 75.2 (그림 2 왼쪽)
    • 창고 접근: 표준 Θ(Nd+N²) vs 번개 Θ(N²d²/M) (정리 2)
    • 번개 어텐션은 근사가 아니다 — 블록 희소판만 근사
    인턴 모아
