# 인퍼런스 스터디 북 — 연구실 식구들과 읽는 『Inference Engineering』

> AI 모델을 더 빠르고, 더 싸고, 더 안정적으로 돌리려면 무엇을 알아야 할까?

> **여기 포스팅은 스터디 멤버의 발표자료가 아닌 ahnboat.xyz 주인장 안상선이 직접 정리한 자료입니다.**

## 인퍼런스 공장 — 층 = 주차, 색 띠 = 책의 장

표지(목차) 첫 화면은 GPU로 답(토큰)을 만드는 3D 공장 건물입니다. 층을 누르면 그 층의 공정과 해설이 열리고, 각 해설 페이지 첫 화면에는 그 페이지가 맡은 층이 3D로 나와 기계 번호로 페이지 칸을 안내합니다.

| 층 | 공정 | 주차 · 장 |
|---|---|---|
| RF 옥상 연구 전망대 | 공장 밖을 내다본다 — 부록 · 특별편 | 부록 |
| 10F 운영 관제 · 출하장 | 멈추지 않게 운영하고 손님에게 내보낸다 | 10주차 · 7장 운영 |
| 9F 출하 준비실 | 포장하고, 늘렸다 줄였다 — 컨테이너와 자동 확장 | 9주차 · 7장 운영 |
| 8F 다품종 라인 | 글만이 아니다 — 그림 · 소리 · 영상을 받고 내보내는 라인 | 8주차 · 6장 입출력 유형 |
| 7F 튜닝 공방 ② | 다시 쓰고, 나눠 싣고, 갈라 세운다 — 캐시 · 병렬화 · 분리 | 7주차 · 5장 최적화 기법 |
| 6F 튜닝 공방 ① | 같은 기계로 더 빨리 — 숫자를 줄이고, 초안을 먼저 쓰고 검수한다 | 6주차 · 5장 최적화 기법 |
| 5F 엔진 제어실 | 기계를 움직이는 소프트웨어 — CUDA부터 추론 엔진, 부하 시험까지 | 5주차 · 4장 소프트웨어 |
| 4F GPU 기계실 | 공장의 엔진룸 — GPU의 구조와 세대, 빌려 쓰는 단위 | 4주차 · 3장 하드웨어 |
| 3F 병목 진단실 | 느린 곳을 찾는다 — 계산이 막혔나, 메모리 통로가 막혔나 | 3주차 · 2장 모델 |
| 2F 모델 조립 라인 | 모델이라는 기계를 뜯어 본다 — 토큰 하나가 층을 지나 다음 토큰이 되기까지 | 2주차 · 2장 모델 |
| 1F 정문 · 설계실 | 주문 접수와 설계 — 무엇을, 누구에게, 어떤 눈금으로 만들지 정한다 | 1주차 · 서문 · 0장 · 1장 |

## 그래서, GPU로 LLM을 어떻게 돌리나 — 추론 공정 제어판

책 한 권을 한 장으로 줄인 순서입니다. 목차 첫 화면에 전체가 있고, 해설 페이지마다 첫 화면(공장 층 아래)에 **"그래서 이 편에서 돌리는 다이얼은?"** 상자가 다시 나와 그 편이 맡은 단계와 다이얼에 불이 켜집니다.

| 단계 | 하는 일 |
|---|---|
| ① 목표 정하기 | 빨리(지연시간) · 많이(처리량) · 싸게(비용) 중 무엇을 먼저 지킬까 |
| ② 모델 성질 보기 | 질문 읽기(프리필)는 계산이, 한 토큰씩 쓰기(디코드)는 메모리 통로가 막힌다 |
| ③ 기계 맞추기 | 모델이 VRAM에 들어가나, 메모리 대역폭은 충분한가 |
| ④ 다이얼 돌리기 | 배치 · 정밀도(양자화) · KV 캐시 · 나눠 싣기(병렬화·분리) · 계산 방식(커널) |
| ⑤ 재고 병목 찾기 | 계기판(TTFT · TPS · P99)과 루프라인으로 막힌 곳을 찾고 → 다시 ②로 |

다이얼 다섯은 설명을 위해 묶은 것이며 책의 공식 분류는 아닙니다. 업계 말로는 추론 최적화 · 서빙 최적화(inference optimization)라고 부릅니다. 데이터는 `tools/lab_build/series.py`의 `FLOW` · `DIALS` · `CARDS`.

## 목록 카드 한 틀 (썸네일 · 제목 · 소개)

ahnboat.xyz 카탈로그 등 목록에 나가는 카드는 모든 편이 같은 틀을 씁니다. 기준 파일은 루트의 [`catalog_cards.json`](catalog_cards.json)이고, 목록은 **책의 장 순서**로 묶습니다.

- **썸네일** `<폴더>/thumb.jpg` (1200×630): 위는 그 편이 맡은 공장 층(3D), 아래 흰 띠에 층·주차 / 제목 / 교재·논문 꼬리표, 왼쪽에 장 색 막대
- **제목**: 교재 `{장} · {제목}` (예: 2장 후반 · 병목을 찾아라), 논문 `{장} 논문 · {제목} ({논문 이름})` (예: 2장 논문 · 번개 어텐션 (FlashAttention))
- **소개 한 줄**: "이 편을 읽으면 …할 수 있습니다."
- 짝 저장소(스터디 보드 · 발표 자료)의 카드 그림은 `cards/`에 같은 틀로 둡니다.


## 규칙

- 폴더 이름 = 옛 저장소 이름에서 `inference_engineering_study_`를 뺀 것: `week_{주차}_textbook_{장·범위}`, `week_{주차}_article_{번호}`, 부록은 `special_{번호}`.
- 한 주에 장이 바뀌면 장마다 따로 만든다(예: 3장, 5장, 7장). 큰 장은 범위로 나눈다(`_p1_p2`, `_p3_to_end`).
- 3주차 교재편(`week_03_textbook_ch02_p3_to_end/`)은 먼저 완성된 원본을 내용 수정 없이 그대로 옮겼다(맨 앞의 공장 층 안내만 덧붙임).
- 나머지 페이지는 연구실 해설 스킬(ai-lab-explainer v1.12, 캐릭터 팩 1.4) 규격으로 식구 전원이 나오도록 다시 적용했다.
- 모든 페이지는 스킬 v1.14 "낮의 연구실"(흰 배경)이다. 생성기로 만드는 페이지(1·4주차, 목차)는 `light.css`를 바로 쓰고, 옮겨 온 2·3주차 페이지는 `daylight.py`로 흰 화면 색을 덧입혔다(그림 코드에 색이 박힌 그래프·도식은 어두운 모니터 화면으로 둠). 외국어판(`*.en.html` 등)은 이전 판 그대로다.
- 4주차부터 페이지마다 30분 코스(핵심 칸 바로가기)와 강의자용 부록(퀴즈 정답·해설)을 둔다.
- 페이지는 단일 HTML(외부 요청은 글꼴과, 첫 화면 공장 3D의 three.js뿐 — 불러오지 못해도 층·기계 목록 안내는 그대로 동작), 페이지마다 지식 색인(`#kg`)과 온톨로지·서지 꾸러미(`#export`)가 있다.
- 글 표지는 지금 대체 표지(여섯 식구 표정 그림 줄 세우기)이고, 그림 지시문은 폴더마다 `COVER_*.md`에 있다.
