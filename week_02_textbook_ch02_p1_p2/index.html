2F 모델 조립 라인

모델이라는 기계를 뜯어 본다 — 토큰 하나가 층을 지나 다음 토큰이 되기까지

인턴 시아 · 공정 안내

여기는 2F 모델 조립 라인이에요. 토큰 하나가 층을 지나 다음 토큰이 되기까지. 이 해설은 이 층의 기계 4대를 맡았어요. 번호를 누르면 그 칸으로 내려갑니다.

    그래서 이 편에서 돌리는 다이얼은?

    모델 안의 공정을 알아야 다이얼 손잡이마다 무슨 뜻인지 보입니다.

    1. ① 목표 정하기빨리(지연시간) · 많이(처리량) · 싸게(비용) 중 무엇을 먼저 지킬까
    2. ② 모델 성질 보기질문 읽기(프리필)는 계산이 막히고, 한 토큰씩 쓰기(디코드)는 메모리 통로가 막힌다
    3. ③ 기계 맞추기모델이 VRAM에 들어가나, 메모리 대역폭은 충분한가
    4. ④ 다이얼 돌리기아래 다섯 다이얼을 목표에 맞춰 조절한다
    5. ⑤ 재고 병목 찾기계기판(TTFT · TPS · P99)과 루프라인으로 막힌 곳을 찾고 → 다시 ②로
    • 배치이 편질문 읽기(프리필)와 한 토큰씩 쓰기(디코드)는 성질이 달라서 배치의 효과도 다릅니다.
    • 정밀도이 편모델이 하는 일 대부분이 숫자 표 곱하기라, 숫자 크기가 곧 메모리와 속도입니다.
    • KV 캐시이 편KV 캐시가 처음 나옵니다 — 앞 토큰을 매번 다시 계산하지 않으려고 쌓아 두는 메모예요.
    • 나눠 싣기모델과 공정을 GPU 여러 대에 어떻게 나눌까 (병렬화 · 분리) — 한 대에 안 들어가거나 더 빨라야 할 때 쓴다
    • 계산 방식같은 답을 어떤 순서로 계산할까 (커널) — 메모리 왕복을 줄이면 답은 같고 빨라진다

    불이 켜진 단계와 다이얼이 이 편이 맡은 자리입니다. 회색은 다른 편에서 다룹니다.

    인퍼런스 엔지니어링은 생성 AI 모델을 더 빠르게, 더 싸게, 더 믿을 수 있게 돌리되 품질은 지키는 일입니다[1]. 그러려면 모델이 속에서 어떻게 움직이는지 감이 있어야 합니다. 이 페이지는 행렬곱 한 번에서 출발해 활성화 함수, 토큰과 샘플링, 어텐션과 KV 캐시, 전문가 혼합(MoE)까지 다섯 칸을 올라갑니다. 칸마다 직접 만져 보는 실험이 있습니다.

    왜 모델 속을 알아야 하나

    이유 1

    빠르고 싸게, 품질은 그대로

    책은 인퍼런스 엔지니어링을 "품질을 희생하지 않으면서" 모델을 빠르고 싸고 믿을 만하게 만드는 일로 정의합니다. 무엇을 줄여도 되는지 알려면 모델 안에서 무엇이 일하는지 알아야 합니다[1].

    이유 2

    시간은 두 곳에서 쓰인다

    추론 시간과 자원의 대부분은 프리필에서 KV 캐시를 만드는 일과 디코드에서 로짓을 만드는 일에 쓰입니다. 둘 다 큰 신경망을 돌리기 때문입니다[1].

    이유 3

    아키텍처가 엔진 지원을 정한다

    같은 아키텍처라면 크기·변형·파인튜닝이 달라도 잘 최적화된 배포를 그대로 쓸 수 있습니다. 그래서 config.json의 이름 한 줄을 읽는 법부터 배웁니다[1].

    박사

    박사의 한 줄: 속도를 사려면 어디서 시간이 새는지부터 알아야 해요.

    큰 그림 — 주문에서 다음 토큰까지

    트랜스포머 기반 생성 모델은 두 갈래입니다. 자기회귀 토큰 생성은 토큰 열에서 다음 토큰을 예측하고(LLM), 반복 노이즈 제거는 무작위 노이즈에서 출발해 확산으로 결과를 다듬습니다(이미지 생성)[1]. 이 페이지는 앞쪽, LLM을 다룹니다. 이미지 생성은 책의 2.3절에서 이어집니다.

    0 토큰화 (채팅 템플릿)1 프리필 → KV 캐시2 디코드: 한 번의 순전파 = 토큰 하나3 로짓 → 확률 → 뽑기4 멈춤 토큰 · 문맥 창 · max_tokens

    인코더와 디코더

    인코더는 입력을 의미가 담긴 내부 표현으로 만들고, 디코더는 그 표현으로 출력을 만듭니다. 요즘 LLM은 디코더 전용이고, 인코더 전용은 BERT 계열 임베딩 모델처럼 드뭅니다. 음성 받아쓰기 모델 Whisper는 인코더-디코더입니다[1].

    짧은 역사

    1950년대 하드웨어 퍼셉트론 → 역전파로 다층 퍼셉트론 → 2000년대 깊은 신경망 → 2012년 AlexNet이 GPU의 힘을 보여 줌 → 2017년 「Attention Is All You Need」가 트랜스포머를 소개[1][2].

    1기초

    선형층과 행렬곱 — 신경망의 기본 동작

    모델: y = xW + b일상: 소스 배합표

    일상으로 치면

    재료 양(입력)에 배합표의 비율(가중치)을 곱해 더하고, 기본 간(편향)을 얹으면 소스 맛 점수(출력)가 나옵니다. 배합표를 두 번 거쳐도, 두 표를 미리 곱해 둔 표 한 장으로 똑같은 결과를 낼 수 있습니다.

    신경망에서는

    노드는 입력에 가중치를 곱하고 편향을 더해 돌려주는 작은 프로그램이고, 노드가 모이면 층이 됩니다. 선형층은 입력 벡터에 가중치 행렬을 곱하고 편향 벡터를 더합니다. 두 선형층은 행렬을 곱해 합친 한 층과 같습니다[1].

    실험 ① — 두 층을 지난 격자 vs 합친 한 층을 지난 격자

    그리기
    두 층 사이
    35°

    행동으로 보기 — 점 하나가 두 길로 간다

    풀이 — 왜 합쳐지나

    1. 층 1: y = xW₁ + b₁. 층 2: z = yW₂ + b₂.
    2. 층 1을 층 2에 넣으면 z = x(W₁W₂) + (b₁W₂ + b₂).
    3. W₃ = W₁W₂, b₃ = b₁W₂ + b₂로 두면 z = xW₃ + b₃. 층 두 개가 한 개로 접혔습니다. 위 실험에서 두 격자가 한 치도 어긋나지 않는 이유입니다.
    4. LLM의 가중치 대부분은 이런 선형층에 있고, 행렬의 값은 학습 때 정해집니다[1].

    이 칸의 한계: 선형층만 쌓으면 아무리 깊어도 한 층과 같습니다. 층을 쌓는 의미가 없어집니다. → 다음 칸에서 "접히지 않게" 만드는 장치가 나옵니다.

    수식으로 보기

    x ∈ ℝ1×d, W₁ ∈ ℝd×h, W₂ ∈ ℝh×k이면 W₃ = W₁W₂ ∈ ℝd×k. 행렬곱의 결합법칙 (xW₁)W₂ = x(W₁W₂) 때문입니다. 책의 그림 2.3이 이 계산을 그대로 보여 줍니다[1].

    조수

    두 길의 도착점 차이를 재 봤어요. 위 숫자 그대로, 사이에 아무것도 없으면 0이에요.

    2기초

    활성화 함수 — 층이 접히지 않게 꺾기

    모델: ReLU(x) = max(0, x)초파리: 발화 문턱 (보조 비유)

    초파리에서는

    초파리 뉴런은 입력이 문턱을 넘어야 발화합니다. 문턱 아래 입력은 그냥 사라집니다. 받은 신호를 "그대로 더하기만" 하지 않는다는 점이 ReLU와 닮았습니다.

    한계: 실제 뉴런은 전기 신호(스파이크)를 내고, ReLU처럼 입력에 정비례하는 값을 내지 않습니다.

    신경망에서는

    활성화 함수는 비선형이라 행렬곱이 한 층으로 접히는 것을 막고, (거의) 미분 가능해서 역전파 학습을 돕습니다. ReLU는 x가 0보다 크면 x, 아니면 0을 돌려줍니다. ReLU, SiLU, Swish, SwiGLU는 빠르고 학습하기 쉽습니다[1].

    실험 ② — 원판과 고리를 가르기 (은닉 노드 8개)

    활성화

    행동으로 보기 — 검증 접시를 하나씩 판정

    풀이 — 꺾는 선이 모이면 곡선이 된다

    1. 활성화가 없으면 은닉층이 있어도 모델 전체가 한 선형층과 같아서 경계는 곧은 선 하나입니다. 원판과 고리는 곧은 선으로 가를 수 없습니다.
    2. ReLU는 음수를 0으로 꺾습니다. 꺾인 면 여러 장이 겹치면 둥근 경계를 흉내 낼 수 있습니다.
    3. SiLU처럼 음수 쪽을 부드럽게 0 근처로 보내는 함수도 같은 일을 합니다. 책은 대부분의 활성화 함수가 "음수는 0 근처로, 양수는 그대로"라는 같은 틀을 따른다고 설명합니다[1].
    4. 점수는 훈련에 쓰지 않은 검증 점으로 매깁니다.

    이 칸의 한계: 신경망은 숫자 벡터만 받고 숫자 벡터만 냅니다. 글자를 직접 받을 수도, 글자로 답할 수도 없습니다. → 다음 칸: 토큰.

    수식으로 보기

    은닉 h = φ(xW₁ + b₁), 출력 p = σ(hW₂ + b₂). φ가 항등 함수이면 p = σ(x(W₁W₂) + …)라서 경계 xW₃ + b₃ = 0은 직선입니다. ReLU(z) = max(0, z), SiLU(z) = z·σ(z). 학습: 교차 엔트로피, 전체 배치 경사하강, 학습률 0.8, 시드 3(가중치)·5(훈련)·77(검증).

    초파리 연구원

    훈련 점수 말고 속 빈 점(검증) 점수부터 봐. 그게 진짜야.

    3중급

    토큰과 다음 토큰 고르기

    모델: 로짓 → 확률 → 뽑기일상: 주문을 메뉴 번호로 적기

    주방에서는

    손님 말을 그대로 넘기지 않고 메뉴판 번호로 적어 주방에 넘깁니다. 번호 바꾸기는 요리사가 아니라 표 한 장이 합니다. 자주 나가는 메뉴는 번호 하나, 드문 주문은 번호 여러 개를 붙여 적습니다.

    한계: 메뉴 번호는 사람이 정하지만, 토크나이저의 어휘는 데이터에서 만들어지고 모델마다 다릅니다.

    신경망에서는

    토큰은 글 조각을 나타내는 숫자입니다. 요즘 LLM은 서브워드 토큰화를 써서 토큰 하나가 단어 하나이거나 단어의 일부입니다. 토크나이저는 신경망 없이 문자열과 숫자를 짝짓는 표이고, 모델의 출력층은 어휘 크기만큼 긴 로짓 벡터를 냅니다[1].

    책의 예문 — 6단어 41글자가 8토큰

    토큰 번호는 책 그림 2.5 그대로입니다[1]. 흔하지 않은 단어 "Inference"는 두 토큰으로 쪼개졌습니다. 토큰이 적을수록 같은 출력을 더 빨리 끝냅니다.

    행동으로 보기 — 한 토큰씩 이어 쓰기 (같은 온도·top-k·top-p)

    시드 1

    풀이 — 토큰 하나가 나오는 다섯 걸음

    1. 입력(프롬프트·대화·도구 설명)에 채팅 템플릿을 씌워 한 줄로 만들고 토큰화합니다. 이것이 추론의 0단계입니다.
    2. 모델이 어휘의 모든 토큰에 대해 로짓을 냅니다.
    3. 로짓을 정규화하면 확률이 됩니다. 온도는 정규화 전에 로짓 자체를 조정합니다.
    4. top-k는 확률 상위 k개만, top-p는 확률을 더해 p가 되는 가장 작은 묶음만 남기고 다시 정규화합니다.
    5. 남은 확률대로 무작위로 하나를 뽑습니다. 온도 0이나 top-k 1이면 늘 가장 높은 토큰을 고릅니다. 멈춤 토큰이 나오거나 문맥 창·max_tokens에 닿으면 끝납니다[1].

    이 칸의 한계: 다음 토큰을 고르려면 앞의 모든 토큰을 참고해야 합니다. 문장이 길어질수록 무엇을 얼마나 참고할지 정하는 장치가 필요합니다. → 다음 칸: 어텐션.

    수식으로 보기

    pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T). T → 0이면 argmax. top-k: 상위 k개 집합 S에서 pᵢ/ΣSp. top-p: 내림차순 누적합이 처음 p 이상이 되는 집합. 구조화 출력(JSON 등)에서는 순전파 뒤에 로짓 바이어스 같은 도구를 더 씁니다[1].

    비유의 한계: 실제 어휘는 10만 개가 넘고, 후보 8개짜리 막대는 그중 맨 앞만 잘라 본 예시입니다.

    어텐션과 KV 캐시 — 앞 토큰을 어떻게 참고하나

    모델: softmax(QKᵀ/√dₖ)V일상: 밑손질해 둔 재료통

    주방에서는

    주문서를 받으면 먼저 재료를 모두 손질해 통에 담아 둡니다(프리필). 그다음 한 접시씩 낼 때마다 손질된 통을 꺼내 쓰고, 새 접시의 재료통 하나를 더 쌓습니다(디코드). 매 접시마다 처음부터 다시 손질하지 않습니다.

    한계: 재료는 쓰면 줄지만 KV 캐시는 토큰마다·층마다 계속 늘어나 GPU 메모리를 차지합니다.

    신경망에서는

    어텐션은 지금 토큰(Q)과 앞 토큰들의 표현(K)을 견주어 가중치를 정하고, 앞 토큰들의 값(V)을 그만큼 섞습니다. 앞 토큰의 K·V를 GPU 메모리의 KV 캐시에 저장해 두고 다시 계산하지 않습니다[1].

    실험 ④-가 — 책의 예문에서 "it"이 보는 곳 (인과 마스크)

    실험 ④-나 — KV 캐시가 있을 때와 없을 때 K·V 계산 횟수

    500
    500

    행동으로 보기 — 주방의 프리필과 디코드

    풀이 — Q, K, V와 두 단계

    1. Q(질의): 지금 만들거나 고치는 토큰의 표현. K(키): 앞 토큰들의 표현. V(값): 앞 토큰들의 계산된 값[1].
    2. LLM은 셀프 어텐션(Q·K·V가 같은 열에서 옴)에 인과 마스크를 씌워 뒤 토큰을 못 보게 합니다. 이미지·멀티모달 모델은 크로스 어텐션도 씁니다[1].
    3. 어텐션 층은 여러 머리(head)가 나란히 돕니다. 머리마다 주어-동사 일치, 지칭 같은 다른 관계를 맡을 수 있습니다[1].
    4. 어텐션은 지금 토큰과 앞의 모든 토큰의 관계를 보므로 문장 길이에 대해 제곱 시간입니다. 책은 KV 캐시 덕분에 실제로는 선형으로 돈다고 설명합니다. 토큰 하나를 만들 때 앞 토큰의 K·V를 다시 계산하지 않고 캐시에서 꺼내기 때문입니다[1].
    5. KV 캐시는 프리필에서 만들어지고, 디코드에서 쓰이며 갱신되고, 기본적으로 GPU 메모리에 삽니다. 저장·재사용은 책 5.3절의 큰 주제입니다[1].

    이 칸의 한계: 가중치가 가장 많은 곳은 어텐션이 아니라 피드포워드(선형) 층입니다. 토큰 하나마다 이 거대한 행렬 전체를 지나야 합니다. → 다음 칸: 일부만 쓰는 전문가 혼합.

    수식으로 보기

    Attention(Q, K, V) = softmax(QKᵀ/√dₖ)V (Vaswani 외 2017; 책은 Dao 외 2022의 표기를 따름)[1][2][3]. 위 실험 ④-나의 셈: 프롬프트 P, 출력 N일 때 캐시 없음 = Σt=1..N(P+t) = NP + N(N+1)/2, 캐시 있음 = P + N. 매 단계 내적 계산(P+t번)은 두 경우 모두 같고, 캐시가 줄이는 것은 앞 토큰 K·V의 재계산입니다.

    생성 AI로 치면

    긴 문서를 붙여 넣으면 첫 글자가 나오기까지 기다리는 시간이 길어지는 것은 프리필, 그 뒤 글자가 흘러나오는 것은 디코드입니다.

    비유의 한계: 실제 서비스의 대기 시간에는 줄 서기, 네트워크 등 다른 요인도 섞입니다.

    현장에 옮기면

    KV 캐시는 동시 요청 수 × 문맥 길이만큼 GPU 메모리를 먹습니다. 서비스 설계 때 "가중치 메모리"와 별도로 "캐시 메모리" 예산을 잡아야 합니다.

    비유의 한계: 실제 크기는 층 수·KV 머리 수·정밀도에 따라 달라지며 이 페이지는 칸 수만 셉니다.
    박사

    박사의 한 줄: 한 번 손질한 재료는 다시 손질하지 않는다. 그게 KV 캐시예요.

    전문가 혼합(MoE) — 거대한 행렬 대신 작은 전문가들

    모델: 라우터가 128명 중 8명 선택일상: 주방장이 전문 요리사 배정

    이름 읽는 법 — Qwen3MoeForCausalLM

    Qwen모델 가족(브랜드 이름)
    3가족 안의 아키텍처 주 버전
    Moe전문가 혼합 모델
    CausalLM인과 언어 모델: 앞 토큰만 보고 다음을 예측

    책의 풀이 그대로입니다[1]. 인과 언어 모델은 양쪽 문맥으로 빈칸을 채우는 마스크 언어 모델과 다르며, 오늘날 생성 LLM은 모두 인과 언어 모델입니다. 같은 아키텍처 안에도 여러 크기(예: Llama 8B·70B), base·instruct 변형, LoRA 같은 파인튜닝이 있지만 아키텍처는 바뀌지 않습니다.

    주방에서는

    요리사 한 명이 모든 요리를 하는 대신 전문 요리사 128명을 두고, 주방장(라우터)이 접시마다 8명만 부릅니다. 손님 한 명이면 8명만 바쁩니다. 그런데 저녁 장사로 손님이 몰리면 접시마다 다른 요리사를 부르니 결국 거의 모두가 바빠집니다.

    한계: 실제 라우터는 접시마다 한 번이 아니라 94개 층마다 다시 고릅니다. 그리고 쉬는 전문가도 메모리에는 올라가 있어야 합니다.

    신경망에서는

    MoE는 선형층에 희소성을 더합니다. 큰 행렬 하나 대신 작은 행렬(전문가) 수백 개를 두고 입력마다 몇 개만 활성화합니다. Qwen3-235B-A22B는 요청당 2,350억 중 220억 파라미터를, 128 전문가 중 8개를 94개 층마다 고릅니다. 배치 추론에서는 요청마다 다른 전문가를 켜므로 거의 모든 파라미터가 활성이라고 봐야 합니다[1].

    실험 ⑤ — 한 층, 128 전문가, 배치 크기를 바꾸며

    1

    행동으로 보기 — 주방장이 토큰을 전문가에게 보낸다

    풀이 — 혼자 쓸 때와 서버에서 쓸 때

    1. 신경망의 밀도는 층 사이 연결 수로 정해집니다. 빽빽할수록 정보를 많이 담고, 듬성할수록 계산·메모리가 적게 듭니다[1].
    2. 요청 하나를 혼자 돌리면 활성 파라미터가 적어서 MoE가 매우 효율적입니다(로컬 단일 요청).
    3. 배치를 키우면 토큰마다 고르는 전문가가 달라 켜진 전문가의 합집합이 빠르게 커집니다. 위 실험에서 배치 64면 대부분이 켜집니다.
    4. 그래서 대규모 서비스에서는 여러 GPU에 전문가를 나눠 싣는 전문가 병렬화로 희소성을 살립니다. 책 그림 2.9의 예는 GPU 8대가 전문가를 16개씩 맡고, 라우터는 GPU마다 복제합니다[1].
    5. 32B 미만, 특히 8B 미만 모델은 전통적인 밀집 구조가 효율적인 편이고, 탭 자동 완성처럼 좁은 분야 모델은 모델 전체가 사실상 전문가 하나라 MoE 이득이 적습니다[1].

    이 칸의 한계: 활성 파라미터 수만으로 서버 비용을 셀 수 없습니다. 배치·병렬화 방식·메모리를 함께 봐야 합니다. 그 계산(연산 대 바이트 비율, 병목)은 책 2.4절과 5.4.2절에서 이어집니다.

    수식으로 보기

    전문가 E개 중 토큰마다 K개를 고르고, 라우팅이 고르게 퍼진다고 가정하면 배치 B에서 한 전문가가 한 번도 안 뽑힐 확률은 (1 − K/E)B, 켜진 비율의 기댓값은 1 − (1 − K/E)B입니다. E = 128, K = 8, B = 64이면 1 − (15/16)64 ≈ 0.984. 위 실험은 인기 있는 전문가가 있는 쏠린 라우팅(시드 2026)을 써서 이 값보다 조금 낮게 나옵니다. 둘 다 설명용 모형입니다.

    현장에 옮기면

    "활성 22B"라는 이름표를 보고 22B짜리 GPU 메모리만 준비하면 안 됩니다. 전문가는 전부 메모리에 올라가야 하고, 배치를 키우면 단계마다 거의 모든 전문가 가중치를 읽게 됩니다.

    비유의 한계: 실제 라우팅 분포는 모델과 데이터마다 다르며, 이 페이지의 쏠림 정도는 가정입니다.

    대결 — 서버에서 MoE는 정말 16분의 1만 일할까?

    조건: Qwen3식 MoE 층(전문가 128, 토큰마다 8), 서비스 서버의 디코드 한 단계에 토큰 64개가 함께 들어온다(배치 64). 94개 층에서 "이번 단계에 켜진 전문가 비율"을 재고, 각자의 예측과 비교합니다. 판정 기준은 예측 오차(작을수록 좋음)입니다.

    Hugging Face의 모든 LLM에 있는 수십 줄짜리 파일. 아키텍처 이름과 층·벡터의 크기가 적혀 있다[1].

    비유가 어긋나는 곳

    • 배합표 비유는 행렬의 "곱하고 더하기"만 닮았습니다. 실제 행렬은 수천 × 수천 크기이고 값은 학습으로 정해집니다.
    • 초파리 발화 문턱은 "꺾는다"는 점만 닮았습니다. 신경망은 초파리 뇌를 흉내 낸 것이 아니라 뼈대를 빌려 왔을 뿐입니다.
    • 어텐션은 사람의 주의 집중에서 이름만 빌렸습니다. 실제로는 내적과 소프트맥스 계산입니다.
    • 주방 비유의 "요리사 인건비"는 MoE의 계산량과 닮았지만, 쉬는 전문가도 GPU 메모리 자리는 차지한다는 점이 다릅니다.

    모아의 기록장

    • 선형층 두 개는 행렬곱으로 한 층에 접힌다 → 활성화 함수가 접힘을 막는다
    • 대부분 모델의 어휘 크기는 100,000개 이상
    • Qwen3: 전체 235B 중 요청당 22B 활성, 전문가 128명 중 8명, 94층
    • 추론 시간 대부분은 프리필(KV 캐시 만들기)과 디코드(로짓 만들기)
